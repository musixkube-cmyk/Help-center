    12→## 1. Experience Principles
    13→
    14→These are the filters every design and engineering decision runs through. If a proposed pattern violates one of these, it doesn't ship, regardless of how good it looks in isolation.
    15→
    16→| Principle | What it means in practice |
    17→|---|---|
    18→| **Minimalism** | One idea per section. No section carries more than one primary CTA. Whitespace is a component, not a gap. |
    19→| **Cinematic storytelling** | Sections reveal in sequence, not all at once. The scroll is a timeline, not a list. |
    20→| **High motion, low distraction** | Motion always communicates state or hierarchy (what changed, what's next). Motion never exists purely for decoration with no informational payload. |
    21→| **Touch-first interactions** | Every desktop interaction (pointer drag, hover) has a touch-equivalent (finger drag, tap-and-hold) designed first, not adapted after. |
    22→| **Scroll-driven narrative** | The primary navigation mechanism on marketing pages is scroll, not clicks. Scroll position is treated as application state. |
    23→| **Accessibility** | Every interactive element is keyboard-reachable and screen-reader-labeled. Motion respects `prefers-reduced-motion` without exception. |
    24→| **Performance-first** | A beautiful interaction that costs Lighthouse points below 90 is a rejected interaction, not a trade-off to negotiate. |
    25→| **Mobile-first** | Every blueprint and component is designed at 375px width first. Desktop is the enhancement, not the baseline. |
    26→| **Progressive enhancement** | The page is fully readable and navigable with zero JS motion. GSAP/Three.js/Framer Motion layer on top of a working, semantic HTML page — they never gate content visibility. |

    30→## 2. Technology Stack
    31→
    32→| Layer | Library | Version target | Purpose | Rendering boundary |
    33→|---|---|---|---|---|
    34→| Framework | Next.js | 14+ (App Router) | Routing, SSG/ISR, image optimization | Server by default |
    35→| UI | React | 18+ | Component model | — |
    36→| Language | TypeScript | 5+ | Type safety across slot data → component props | — |
    37→| Styling | Tailwind CSS | 3+ | Utility-first responsive styling, design tokens | — |
    38→| Timeline animation | GSAP + ScrollTrigger | 3.12+ | Scroll-synced, multi-step, pinned timeline animations (Hero Rotation, Scroll Lock Hero, Bento Stack) | Client component only |
    39→| Micro-interaction | Framer Motion | 11+ | Hover, tap, entrance/exit, layout transitions on discrete components | Client component only |
    40→| 3D | Three.js + React Three Fiber + Drei | R3F 8+ | Hero 3D scenes, interactive models, particles, lighting, camera rigs | Client component only, lazy-loaded |
    41→| 3D authoring | Blender | 4.x | Source `.blend` files for all 3D assets, exported to `.glb` | Asset pipeline, not runtime |
    42→| Vector animation | Lottie (lottie-react) | latest | Icon animation, empty states, small looping motifs | Client component, lazy-loaded |
    43→| Scroll engine | Lenis | latest | Smooth scroll, scroll synchronization for GSAP ScrollTrigger, parallax | Client-side, wraps app root |
    44→| Audio | Howler.js | latest | Ambient loops, hover feedback, micro-interaction sound | Client component, user-gesture-gated (see §10) |
    45→| SEO | Next.js Metadata API + `next-seo` OG helpers | — | Per-page `generateMetadata`, OG/Twitter cards | Server |
    46→| Forms | React Hook Form + Zod | latest | Newsletter, contact, demo request | Client component |
    47→
    48→**Rendering rule of thumb:** Server Components render the page shell, copy, and static structure. Client Components are reserved for anything that touches `window`, animates on interaction, or holds local UI state (GSAP, Framer Motion, R3F, Lenis, Howler). This boundary is non-negotiable — see Implementation Rules §10.

    52→## 3. Animation Library
    53→
    54→Every animation used anywhere on the marketing site is named here. A blueprint or page spec never invents a new animation inline — it references one of these by name. If a new visual effect is needed, it gets added here first, with a name, before any page uses it.
    55→
    56→| Name | Trigger | Behavior | Library | Reduced-motion fallback |
    57→|---|---|---|---|---|
    58→| **Intro Reveal** | Page load (Home only) | Fullscreen intro sequence: logo forms from particles → dissolves → reveals hero. 1.2–2s max. | GSAP timeline | Static logo, instant hero |
    59→| **Hero Rotation** | Pointer move / touch drag (Home hero only) | 3D model rotates on Y-axis tracking pointer position; inertia + easing on release | R3F + Drei `OrbitControls` (custom-constrained) | Model renders static at default angle |
    60→| **Scroll Lock Hero** | Scroll (Home hero only) | Hero pins in viewport; scroll input drives camera move / model transform instead of page scroll until a completion threshold, then releases to normal scroll | GSAP ScrollTrigger (`pin: true`) | Hero scrolls normally, no pin, no camera move |
    61→| **Bento Stack** | Scroll (any Bento Grid component) | Cards animate from offset/rotated resting state into a stacked grid as they enter viewport; slight z-index layering during transition | GSAP ScrollTrigger (`scrub`) | Cards fade in at final position, no stack motion |
    62→| **Card Lift** | Hover / focus (any card component) | `translateY(-8px)`, shadow expands, 200ms ease-out | Framer Motion `whileHover` | Same, but instant (no transition) — hover lift is not motion-heavy enough to need reduced-motion suppression, but transition duration drops to 0 |
    63→| **Text Glide** | Scroll into view (headlines, all blueprints) | Text enters on Y-axis (24px → 0) with opacity fade, staggered per line/word depending on length | Framer Motion `whileInView` | Opacity fade only, no Y translation |
    64→| **Fade Cascade** | Scroll into view (body paragraphs, list items) | Sequential opacity fade, 80ms stagger per child | Framer Motion `staggerChildren` | All children fade in simultaneously |
    65→| **Counter** | Scroll into view (statistics components) | Number animates from 0 to target value over 1.5s, eased | Framer Motion `animate` + `useMotionValue` | Number renders at final value instantly |
    66→| **Morph** | Scroll into view or hover (shape/icon transitions) | SVG path morph between two states | GSAP `MorphSVGPlugin` | Instant swap, no morph |
    67→| **Liquid Reveal** | Scroll into view (image reveals) | Image clip-path animates in an organic liquid-fill pattern from a mask | GSAP + custom SVG mask | Standard opacity fade |
    68→| **Magnetic Button** | Pointer proximity (primary CTAs, desktop only) | Button subtly translates toward cursor within a radius, snaps back on leave | Framer Motion `useMotionValue` + pointer tracking | No magnetic effect, standard hover state only |
    69→| **Cursor Glow** | Pointer move (interactive/3D zones only) | Soft radial gradient follows cursor, blends with background | Custom canvas or CSS `radial-gradient` + RAF | Disabled entirely |
    70→| **Scroll Indicator** | Persistent during Scroll Lock Hero | Small progress dots/bar showing position within locked scroll sequence | Framer Motion | Static, non-animated indicator |
    71→| **Footer Reveal** | Scroll into view (footer, all pages) | Footer rises from behind page content (parallax-style reveal, page content appears to lift off it) | GSAP ScrollTrigger | Footer appears in normal document flow, no parallax |

    75→## 4. Component Library
    76→
    77→Components are the building blocks blueprints compose. Each has defined variants. A page spec (Doc 3) selects a component + variant per slot — it never modifies component behavior inline.
    78→
    79→### Hero
    80→Variants: `standard` · `interactive-3d` · `video` · `split` · `fullscreen-scroll-lock` · `product`
    81→
    82→| Prop slot | Type | Notes |
    83→|---|---|---|
    84→| `headline` | string | Rendered with Text Glide |
    85→| `subhead` | string | Rendered with Fade Cascade |
    86→| `media` | asset path | `.glb` for interactive-3d, `.mp4`/`.webm` for video, `.webp`/`.avif` for standard/product |
    87→| `cta_primary` / `cta_secondary` | `{label, href}` | Magnetic Button on desktop |
    88→| `ambient_audio` | asset path, optional | Only on `interactive-3d` and `fullscreen-scroll-lock` variants; user-gesture-gated |
    89→
    90→### CTA Banner
    91→Variants: `light` · `dark` · `video-bg` · `illustration-bg`
    92→Always positioned directly above the footer, per Page Blueprint rule (§6 of Doc-level rules below), except Home.
    93→
    94→### Bento Grid
    95→Variants by card count: `2` · `3` · `4` · `6` · `9` · `12`
    96→Uses **Bento Stack** animation on scroll entrance. Each card supports **Card Lift** on hover.
    97→
    98→### Feature Grid
    99→Icon + headline + one-line description, 3–6 columns responsive. Uses **Fade Cascade**.
   100→
   101→### Timeline
   102→Vertical or horizontal step sequence (used on Platform, Solution, and How-it-Works content). Uses **Text Glide** per step as it enters viewport.
   103→
   104→### Comparison Table
   105→Used on Comparison blueprint and select Pricing sections. Sticky header row on scroll within table bounds.
   106→
   107→### Testimonial
   108→Variants: `single-quote` · `carousel` · `video-testimonial`
   109→
   110→### Logo Wall
   111→Static or auto-scrolling marquee of partner/customer logos. Respects `prefers-reduced-motion` (marquee pauses, becomes static grid).
   112→
   113→### FAQ
   114→Accordion-based, one item open at a time by default (configurable to allow multiple).
   115→
   116→### Pricing
   117→Variants: `tiered-cards` · `comparison-matrix`. Toggle component for monthly/annual where applicable.
   118→
   119→### Cards
   120→Base card primitive underlying Bento Grid, Feature Grid, and standalone card use.
   121→
   122→### Statistics
   123→Uses **Counter** animation. 2–4 stat blocks per row, responsive to 1 column mobile.
   124→
   125→### Tabs
   126→Used for multi-variant content within one section (e.g., persona sub-views on Solution pages).
   127→
   128→### Accordions
   129→Base primitive underlying FAQ; also used for Documentation blueprint.
   130→
   131→### Forms
   132→`newsletter-inline` · `contact` · `demo-request`. React Hook Form + Zod validation, accessible error states.
   133→
   134→### Newsletter
   135→Footer-embedded and standalone variants of the `newsletter-inline` form.

   207→## 6. Page Blueprints
   208→
   209→**How to read this section:** each blueprint is a literal template with named, typed slots. A page is built by taking one blueprint and filling every slot with the values given for that route in `03-page-data.md`. There is no interpretation step — if a slot has no value in Doc 3 for a given page, that page is incomplete, not "use your judgment."
   210→
   211→Every blueprint except **Home** and **Landing** follows the same 4-section-plus-CTA-plus-footer skeleton described in §6.0. Home and Landing are structurally unique and are specified separately (§7, §6.9).
   212→
   213→### 6.0 Shared skeleton (all blueprints except Home)
   214→
   215→```
   216→[Header — Creative Menu, persistent, see §9]
   217→[Section 1 — Hero]
   218→[Section 2]
   219→[Section 3]
   220→[Section 4]
   221→[CTA Banner — 2-column, animated, directly above footer]
   222→[Footer — Footer Reveal animation]
   223→```
   224→
   225→Each blueprint below defines what Sections 1–4 *mean* for that page type (what content role each section plays), which components fill them, and which slots need data.

   390→## 7. Home Page Blueprint (unique — the exception to §6.0)
   391→
   392→Home does not follow the 4-section-plus-CTA skeleton. It is fullscreen, scroll-locked, and cinematic for its first act, then transitions into a lighter version of the standard pattern for its second act.
   393→
   394→```
   395→[No standard header on load — Creative Menu fades in after Intro Reveal completes]
   396→
   397→ACT I — Immersive (fullscreen, scroll-locked)
   398→  [Intro Reveal]                     — logo particle formation, 1.2-2s, plays once per session
   399→  [Hero — Scroll Lock Hero variant]  — 3D model interactive on pointer/touch (Hero Rotation),
   400→                                        pins in viewport, scroll input drives camera through
   401→                                        3–4 "beats" that introduce the platform concept
   402→                                        (Artist → Studio → Enterprise → Streaming, one beat each)

   569→## 10. Implementation Rules (non-negotiable)
   570→
   571→1. Every animation must degrade gracefully — a broken/unloaded asset never blocks page content from being visible or readable.
   572→2. No animation blocks interaction — a user can always scroll past, tab past, or click through an in-progress animation.
   573→3. All motion respects `prefers-reduced-motion: reduce` — see per-animation fallback column in §3.
   574→4. All 3D assets (`.glb`) lazy-load, code-split from the main bundle, with a static poster image (`hero-bg.webp`) shown until the 3D scene mounts.
   575→5. Videos pause when scrolled off-screen (IntersectionObserver-gated `play()`/`pause()`).
   576→6. All images use `next/image` — no raw `<img>` tags anywhere in the codebase.
   577→7. GSAP + ScrollTrigger owns timeline/scroll-scrubbed animation. Framer Motion owns discrete UI state transitions (hover, tap, mount/unmount, layout). These two libraries are never used to animate the same property on the same element.
   578→8. Three.js/R3F is reserved for genuinely immersive scenes (Home hero, and any page-specific `interactive-3d` Hero variant called out in Doc 3) — it is never used for simple icon or decorative motion where Lottie or CSS suffices.
   579→9. Components are Server Components by default. A component becomes a Client Component only when it directly uses `useState`/`useEffect`/`useRef` for animation, browser APIs, or the libraries in §2. This boundary is enforced at the component-file level — a Server Component wraps and lazy-loads Client Component islands, never the reverse.
   580→10. Audio (Howler) never autoplays on page load without an explicit prior user gesture (click/tap) — browser autoplay policy compliance and user-respect both require this. Ambient audio starts muted with a visible unmute toggle.
   581→11. Every page must score 90+ on Lighthouse (Performance, Accessibility, Best Practices, SEO) in production build — this is a merge-blocking CI check, not a goal.
   582→12. Every interactive element supports both keyboard navigation (visible focus states, logical tab order) and touch input — no hover-only interactions gate access to content or navigation.
   583→13. All assets ship in modern formats: images as WebP with AVIF fallback disabled where AVIF is primary (`next/image` handles negotiation), 3D as compressed/Draco-encoded `.glb`, video as adaptive MP4 (H.264 baseline) + WebM.
   584→14. Every page defines its own `generateMetadata` (title, description, OG image, canonical URL) — no page inherits a generic fallback in production.
   585→15. No `#` hash-fragment routing anywhere (carried forward from the Route Map's own rule) — every SEO-relevant surface is a real file-system route with its own `page.tsx`.
