# Musicosy — Marketing Experience & Component Library

*Canonical specification. This document defines HOW every marketing page behaves. It does not define what any single page says — that lives in `03-page-data.md` (per-route content) and is assembled via the blueprints below. Nothing in this file is page-specific; if you find yourself writing content here, it belongs in Doc 3.*

Companion documents:
- `02-information-architecture.md` — full sitemap, every route, blueprint assignment
- `03-page-data.md` — per-route slot data (headlines, copy, asset paths, component composition)
- `public/` — scaffolded asset tree with placeholder files matching the path patterns defined here

## 1. Experience Principles

These are the filters every design and engineering decision runs through. If a proposed pattern violates one of these, it doesn't ship, regardless of how good it looks in isolation.

| Principle | What it means in practice |
|---|---|
| **Minimalism** | One idea per section. No section carries more than one primary CTA. Whitespace is a component, not a gap. |
| **Cinematic storytelling** | Sections reveal in sequence, not all at once. The scroll is a timeline, not a list. |
| **High motion, low distraction** | Motion always communicates state or hierarchy (what changed, what's next). Motion never exists purely for decoration with no informational payload. |
| **Touch-first interactions** | Every desktop interaction (pointer drag, hover) has a touch-equivalent (finger drag, tap-and-hold) designed first, not adapted after. |
| **Scroll-driven narrative** | The primary navigation mechanism on marketing pages is scroll, not clicks. Scroll position is treated as application state. |
| **Accessibility** | Every interactive element is keyboard-reachable and screen-reader-labeled. Motion respects `prefers-reduced-motion` without exception. |
| **Performance-first** | A beautiful interaction that costs Lighthouse points below 90 is a rejected interaction, not a trade-off to negotiate. |
| **Mobile-first** | Every blueprint and component is designed at 375px width first. Desktop is the enhancement, not the baseline. |
| **Progressive enhancement** | The page is fully readable and navigable with zero JS motion. GSAP/Three.js/Framer Motion layer on top of a working, semantic HTML page — they never gate content visibility. |

## 2. Technology Stack

| Layer | Library | Version target | Purpose | Rendering boundary |
|---|---|---|---|---|
| Framework | Next.js | 14+ (App Router) | Routing, SSG/ISR, image optimization | Server by default |
| UI | React | 18+ | Component model | — |
| Language | TypeScript | 5+ | Type safety across slot data → component props | — |
| Styling | Tailwind CSS | 3+ | Utility-first responsive styling, design tokens | — |
| Timeline animation | GSAP + ScrollTrigger | 3.12+ | Scroll-synced, multi-step, pinned timeline animations (Hero Rotation, Scroll Lock Hero, Bento Stack) | Client component only |
| Micro-interaction | Framer Motion | 11+ | Hover, tap, entrance/exit, layout transitions on discrete components | Client component only |
| 3D | Three.js + React Three Fiber + Drei | R3F 8+ | Hero 3D scenes, interactive models, particles, lighting, camera rigs | Client component only, lazy-loaded |
| 3D authoring | Blender | 4.x | Source `.blend` files for all 3D assets, exported to `.glb` | Asset pipeline, not runtime |
| Vector animation | Lottie (lottie-react) | latest | Icon animation, empty states, small looping motifs | Client component, lazy-loaded |
| Scroll engine | Lenis | latest | Smooth scroll, scroll synchronization for GSAP ScrollTrigger, parallax | Client-side, wraps app root |
| Audio | Howler.js | latest | Ambient loops, hover feedback, micro-interaction sound | Client component, user-gesture-gated (see §10) |
| SEO | Next.js Metadata API + `next-seo` OG helpers | — | Per-page `generateMetadata`, OG/Twitter cards | Server |
| Forms | React Hook Form + Zod | latest | Newsletter, contact, demo request | Client component |

**Rendering rule of thumb:** Server Components render the page shell, copy, and static structure. Client Components are reserved for anything that touches `window`, animates on interaction, or holds local UI state (GSAP, Framer Motion, R3F, Lenis, Howler). This boundary is non-negotiable — see Implementation Rules §10.

## 3. Animation Library

Every animation used anywhere on the marketing site is named here. A blueprint or page spec never invents a new animation inline — it references one of these by name. If a new visual effect is needed, it gets added here first, with a name, before any page uses it.

| Name | Trigger | Behavior | Library | Reduced-motion fallback |
|---|---|---|---|---|
| **Intro Reveal** | Page load (Home only) | Fullscreen intro sequence: logo forms from particles → dissolves → reveals hero. 1.2–2s max. | GSAP timeline | Static logo, instant hero |
| **Hero Rotation** | Pointer move / touch drag (Home hero only) | 3D model rotates on Y-axis tracking pointer position; inertia + easing on release | R3F + Drei `OrbitControls` (custom-constrained) | Model renders static at default angle |
| **Scroll Lock Hero** | Scroll (Home hero only) | Hero pins in viewport; scroll input drives camera move / model transform instead of page scroll until a completion threshold, then releases to normal scroll | GSAP ScrollTrigger (`pin: true`) | Hero scrolls normally, no pin, no camera move |
| **Bento Stack** | Scroll (any Bento Grid component) | Cards animate from offset/rotated resting state into a stacked grid as they enter viewport; slight z-index layering during transition | GSAP ScrollTrigger (`scrub`) | Cards fade in at final position, no stack motion |
| **Card Lift** | Hover / focus (any card component) | `translateY(-8px)`, shadow expands, 200ms ease-out | Framer Motion `whileHover` | Same, but instant (no transition) — hover lift is not motion-heavy enough to need reduced-motion suppression, but transition duration drops to 0 |
| **Text Glide** | Scroll into view (headlines, all blueprints) | Text enters on Y-axis (24px → 0) with opacity fade, staggered per line/word depending on length | Framer Motion `whileInView` | Opacity fade only, no Y translation |
| **Fade Cascade** | Scroll into view (body paragraphs, list items) | Sequential opacity fade, 80ms stagger per child | Framer Motion `staggerChildren` | All children fade in simultaneously |
| **Counter** | Scroll into view (statistics components) | Number animates from 0 to target value over 1.5s, eased | Framer Motion `animate` + `useMotionValue` | Number renders at final value instantly |
| **Morph** | Scroll into view or hover (shape/icon transitions) | SVG path morph between two states | GSAP `MorphSVGPlugin` | Instant swap, no morph |
| **Liquid Reveal** | Scroll into view (image reveals) | Image clip-path animates in an organic liquid-fill pattern from a mask | GSAP + custom SVG mask | Standard opacity fade |
| **Magnetic Button** | Pointer proximity (primary CTAs, desktop only) | Button subtly translates toward cursor within a radius, snaps back on leave | Framer Motion `useMotionValue` + pointer tracking | No magnetic effect, standard hover state only |
| **Cursor Glow** | Pointer move (interactive/3D zones only) | Soft radial gradient follows cursor, blends with background | Custom canvas or CSS `radial-gradient` + RAF | Disabled entirely |
| **Scroll Indicator** | Persistent during Scroll Lock Hero | Small progress dots/bar showing position within locked scroll sequence | Framer Motion | Static, non-animated indicator |
| **Footer Reveal** | Scroll into view (footer, all pages) | Footer rises from behind page content (parallax-style reveal, page content appears to lift off it) | GSAP ScrollTrigger | Footer appears in normal document flow, no parallax |

## 4. Component Library

Components are the building blocks blueprints compose. Each has defined variants. A page spec (Doc 3) selects a component + variant per slot — it never modifies component behavior inline.

### Hero
Variants: `standard` · `interactive-3d` · `video` · `split` · `fullscreen-scroll-lock` · `product`

| Prop slot | Type | Notes |
|---|---|---|
| `headline` | string | Rendered with Text Glide |
| `subhead` | string | Rendered with Fade Cascade |
| `media` | asset path | `.glb` for interactive-3d, `.mp4`/`.webm` for video, `.webp`/`.avif` for standard/product |
| `cta_primary` / `cta_secondary` | `{label, href}` | Magnetic Button on desktop |
| `ambient_audio` | asset path, optional | Only on `interactive-3d` and `fullscreen-scroll-lock` variants; user-gesture-gated |

### CTA Banner
Variants: `light` · `dark` · `video-bg` · `illustration-bg`
Always positioned directly above the footer, per Page Blueprint rule (§6 of Doc-level rules below), except Home.

### Bento Grid
Variants by card count: `2` · `3` · `4` · `6` · `9` · `12`
Uses **Bento Stack** animation on scroll entrance. Each card supports **Card Lift** on hover.

### Feature Grid
Icon + headline + one-line description, 3–6 columns responsive. Uses **Fade Cascade**.

### Timeline
Vertical or horizontal step sequence (used on Platform, Solution, and How-it-Works content). Uses **Text Glide** per step as it enters viewport.

### Comparison Table
Used on Comparison blueprint and select Pricing sections. Sticky header row on scroll within table bounds.

### Testimonial
Variants: `single-quote` · `carousel` · `video-testimonial`

### Logo Wall
Static or auto-scrolling marquee of partner/customer logos. Respects `prefers-reduced-motion` (marquee pauses, becomes static grid).

### FAQ
Accordion-based, one item open at a time by default (configurable to allow multiple).

### Pricing
Variants: `tiered-cards` · `comparison-matrix`. Toggle component for monthly/annual where applicable.

### Cards
Base card primitive underlying Bento Grid, Feature Grid, and standalone card use.

### Statistics
Uses **Counter** animation. 2–4 stat blocks per row, responsive to 1 column mobile.

### Tabs
Used for multi-variant content within one section (e.g., persona sub-views on Solution pages).

### Accordions
Base primitive underlying FAQ; also used for Documentation blueprint.

### Forms
`newsletter-inline` · `contact` · `demo-request`. React Hook Form + Zod validation, accessible error states.

### Newsletter
Footer-embedded and standalone variants of the `newsletter-inline` form.

## 5. Media Library Specification

Every page's assets live under a predictable path pattern, mirroring the route structure. Claude Code and any contributor can derive the expected asset path for any page/section without a lookup table.

### Path pattern (general rule)

```
public/
  {portal-or-section}/
    {page-slug}/
      hero/
        hero-model.glb          # if 3D hero
        hero-bg.webp            # fallback / poster image
        hero-bg.avif
        hero-video.mp4          # if video hero
        hero-video.webm
        ambient.mp3             # if ambient audio present
      section-2/
        illustration.webp
        illustration.avif
        animation.json          # Lottie, if used
      section-3/
        ...
      og-image.webp             # 1200x630, per-page Open Graph image
```

### Concrete pattern by IA section (see Doc 2 for full route list)

```
public/
  home/
    hero/                       # unique — see §7
    section-1/  ... section-4/
  solutions/
    {audience-slug}/
      {persona-slug}/
        hero/
        section-1/ ... section-4/
  platform/
    {product-slug}/
      hero/
      section-1/ ... section-4/
  features/
    {domain-slug}/
      {feature-slug}/
        hero/
        section-1/ ... section-4/
  integrations/
    {integration-slug}/
      hero/
      section-1/ ... section-4/
  pricing/
    hero/
    section-1/ ... section-4/
  resources/
    {resource-type}/
      {slug}/
  company/
    {page-slug}/
      hero/
      section-1/ ... section-4/
```

Every page directory receives the same skeleton regardless of content: `hero/`, `section-1/` through `section-4/` (or however many sections its blueprint defines), each pre-populated with correctly-named, correctly-formatted **placeholder** files (solid-color `.webp`, 1-second silent `.mp4`, empty `.glb` cube, silent `.mp3`) so the build never breaks on a missing asset — real assets swap in without any path or filename change.

## 6. Page Blueprints

**How to read this section:** each blueprint is a literal template with named, typed slots. A page is built by taking one blueprint and filling every slot with the values given for that route in `03-page-data.md`. There is no interpretation step — if a slot has no value in Doc 3 for a given page, that page is incomplete, not "use your judgment."

Every blueprint except **Home** and **Landing** follows the same 4-section-plus-CTA-plus-footer skeleton described in §6.0. Home and Landing are structurally unique and are specified separately (§7, §6.9).

### 6.0 Shared skeleton (all blueprints except Home)

```
[Header — Creative Menu, persistent, see §9]
[Section 1 — Hero]
[Section 2]
[Section 3]
[Section 4]
[CTA Banner — 2-column, animated, directly above footer]
[Footer — Footer Reveal animation]
```

Each blueprint below defines what Sections 1–4 *mean* for that page type (what content role each section plays), which components fill them, and which slots need data.

## 7. Home Page Blueprint (unique — the exception to §6.0)

Home does not follow the 4-section-plus-CTA skeleton. It is fullscreen, scroll-locked, and cinematic for its first act, then transitions into a lighter version of the standard pattern for its second act.

```
[No standard header on load — Creative Menu fades in after Intro Reveal completes]

ACT I — Immersive (fullscreen, scroll-locked)
  [Intro Reveal]                     — logo particle formation, 1.2-2s, plays once per session
  [Hero — Scroll Lock Hero variant]  — 3D model interactive on pointer/touch (Hero Rotation),
                                        pins in viewport, scroll input drives camera through
                                        3–4 "beats" that introduce the platform concept
                                        (Artist → Studio → Enterprise → Streaming, one beat each)
  [Scroll Indicator]                 — visible throughout Act I only

ACT II — Standard storytelling (unlocks after final beat)
  [Section — Platform Overview]      — Bento Stack grid, one card per portal (6 cards),
                                        each links to that portal's Solutions/Platform page
  [Section — Proof]                  — Statistics (Counter) + Logo Wall (customer/partner logos)
  [Section — Streaming spotlight]    — the one genuinely new surface (per Capability Map §1.1),
                                        video-bg Hero-style module, links to /solutions/fans
                                        and listen.musicosy.com
  [CTA Banner — video-bg variant]
  [Footer — Footer Reveal]
```

### Home Hero slot data

| Slot | Value type | Notes |
|---|---|---|
| `intro_reveal_asset` | `.glb` or Lottie | Logo particle formation source |
| `hero_model` | `.glb` | The central interactive 3D object — see Doc 3 for what this object is |
| `hero_beats[4]` | `{camera_position, headline, subhead}[]` | One per portal category, drives Scroll Lock Hero camera moves |
| `ambient_audio` | `.mp3` | Looping ambient bed, starts muted, user-gesture unmute control visible |
| `og_image` | `.webp` 1200×630 | Home-specific OG image, not auto-generated |

**Media path:** `public/home/hero/`, `public/home/section-1/` (Platform Overview) through `public/home/section-3/` (Streaming spotlight)

**Why Home breaks the pattern:** every other page exists to be found (SEO-driven, long-tail intent) and to convert a specific persona. Home exists to be *experienced* — it's the one page where dwell time and impression are the success metric, not immediate conversion. That's the entire rationale for the Act I / Act II split, and it's why Home is the only page permitted to suppress the standard header on load.

## 9. Interaction Specification

Every non-trivial interaction is documented as an explicit input → response chain. Blueprints reference these by name; they are not redefined per page.

### 9.1 Home Hero — Desktop

```
Pointer movement
  ↓
Model rotates (Hero Rotation, bounded ±45° from resting angle)
  ↓
Lighting rig shifts to follow pointer (R3F directional light target)
  ↓
Contact shadow moves under model
  ↓
Hero headline shifts opacity/position slightly (parallax, 4px max)
  ↓
Particle field (if present) reacts with subtle attraction toward pointer
  ↓
Primary CTA gains Cursor Glow when pointer enters its bounding box
```

### 9.2 Home Hero — Touch

```
Finger drag on model
  ↓
Model rotates 1:1 with drag delta
  ↓
On release: momentum easing continues rotation, decays over ~800ms
  ↓
If no further interaction within 3s: snaps back to resting angle (600ms ease)
  ↓
Vertical scroll gesture (outside model bounding box) advances Scroll Lock Hero beat
```

### 9.3 Scroll Lock Hero — beat advancement (all input types)

```
User scrolls within locked hero region
  ↓
ScrollTrigger progress (0→1) mapped to camera position along predefined path
  ↓
At each beat threshold (0.25, 0.5, 0.75, 1.0): headline/subhead swap (Text Glide out → in)
  ↓
At progress = 1.0: pin releases, normal page scroll resumes, Creative Menu header fades in
  ↓
Scroll Indicator dots update fill state per beat crossed
```

### 9.4 Bento Stack — scroll entrance (any page)

```
Grid container enters viewport (IntersectionObserver / ScrollTrigger start)
  ↓
Cards animate from initial state (offset Y + slight rotation + opacity 0)
  to resting grid position, staggered 60ms per card
  ↓
Scroll continues past grid: cards settle, no further scroll-scrub after full reveal
  ↓
Hover per card: Card Lift
```

### 9.5 Creative Menu — header interaction

```
Default state: minimal, logo + hamburger/menu-trigger only
  ↓
Click/tap trigger
  ↓
Fullscreen (or large panel) menu overlay opens — Framer Motion layout transition
  ↓
Mega-menu categories (Solutions/Platform/Features/Resources/Pricing/Company)
  revealed with Fade Cascade stagger
  ↓
```

## 10. Implementation Rules (non-negotiable)

1. Every animation must degrade gracefully — a broken/unloaded asset never blocks page content from being visible or readable.
2. No animation blocks interaction — a user can always scroll past, tab past, or click through an in-progress animation.
3. All motion respects `prefers-reduced-motion: reduce` — see per-animation fallback column in §3.
4. All 3D assets (`.glb`) lazy-load, code-split from the main bundle, with a static poster image (`hero-bg.webp`) shown until the 3D scene mounts.
5. Videos pause when scrolled off-screen (IntersectionObserver-gated `play()`/`pause()`).
6. All images use `next/image` — no raw `<img>` tags anywhere in the codebase.
7. GSAP + ScrollTrigger owns timeline/scroll-scrubbed animation. Framer Motion owns discrete UI state transitions (hover, tap, mount/unmount, layout). These two libraries are never used to animate the same property on the same element.
8. Three.js/R3F is reserved for genuinely immersive scenes (Home hero, and any page-specific `interactive-3d` Hero variant called out in Doc 3) — it is never used for simple icon or decorative motion where Lottie or CSS suffices.
9. Components are Server Components by default. A component becomes a Client Component only when it directly uses `useState`/`useEffect`/`useRef` for animation, browser APIs, or the libraries in §2. This boundary is enforced at the component-file level — a Server Component wraps and lazy-loads Client Component islands, never the reverse.
10. Audio (Howler) never autoplays on page load without an explicit prior user gesture (click/tap) — browser autoplay policy compliance and user-respect both require this. Ambient audio starts muted with a visible unmute toggle.
11. Every page must score 90+ on Lighthouse (Performance, Accessibility, Best Practices, SEO) in production build — this is a merge-blocking CI check, not a goal.
12. Every interactive element supports both keyboard navigation (visible focus states, logical tab order) and touch input — no hover-only interactions gate access to content or navigation.
13. All assets ship in modern formats: images as WebP with AVIF fallback disabled where AVIF is primary (`next/image` handles negotiation), 3D as compressed/Draco-encoded `.glb`, video as adaptive MP4 (H.264 baseline) + WebM.
14. Every page defines its own `generateMetadata` (title, description, OG image, canonical URL) — no page inherits a generic fallback in production.
15. No `#` hash-fragment routing anywhere (carried forward from the Route Map's own rule) — every SEO-relevant surface is a real file-system route with its own `page.tsx`.
